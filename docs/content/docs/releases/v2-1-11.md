## Added

- **Provider-initiated session revocation** (OpenID Connect Back-Channel
  Logout 1.0): when the identity provider disables a user, logs them out,
  resets their password or MFA, changes their email, or deactivates them via
  SCIM, it now delivers a signed logout token to Buz and every user JWT
  minted at or before that instant is refused — previously such events only
  took effect when the JWT expired (default 24 h).
- `POST /api/v1/auth/oidc/backchannel-logout` (public): validates the logout
  token (RS256 against the provider JWKS with `kid` rotation, `iss`, `aud`,
  `exp` when present, the logout event member, `iat` freshness ≤ 300 s, and
  that no `nonce` is carried), maps the `sub` through the bound identity,
  and stamps the account. Unknown subjects and `sid`-only tokens answer
  `200` (no account enumeration); anything that does not verify answers
  `400`. Revocation is idempotent and audited
  (`auth.oidc_backchannel_logout`, system actor).
- The Settings → SSO page shows the derived back-channel logout URL to
  register at the provider, next to the callback URL.
- No new runtime dependencies; no JWT format change — existing tokens keep
  working, and API tokens (`buz_…`) are deliberately unaffected (they are
  Buz-owned credentials with their own lifecycle; disabling the user still
  blocks them).

## Security notes

- The per-request JWT path compares the token's `iat` against the
  revocation stamp with `<=`, failing closed for tokens minted in the same
  second as the event.
- A misconfigured or unregistered back-channel URL degrades to the old
  behavior (revocation at JWT expiry) — it never blocks sign-in.

## Upgrading

Register `{server.public_base_url}/api/v1/auth/oidc/backchannel-logout` as
the client's back-channel logout URI at your OIDC provider. Without
registration, nothing changes (the JWT TTL governs, as before).

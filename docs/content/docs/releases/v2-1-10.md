## Added

- **OIDC single sign-on** (`[auth.oidc]`, disabled by default): sign in through
  any standards-compliant OIDC provider — authorization code + PKCE S256,
  discovery, JWKS with key-rotation refresh, RS256 `id_token` validation
  (`iss` / `aud` / `exp` / `nonce`). No provider-specific integration; built
  on the existing `jsonwebtoken` + `reqwest`, **no new runtime dependencies**.
- **JIT provisioning** (`auto_provision`, default on): an unbound identity's
  first sign-in creates a plain Buz user — no teams, no admin flags, no local
  password — and the sign-in is audited (`auth.oidc_provision`). Refused for
  an uninitialized instance, so `/setup` always owns the first admin.
- **Account-level authentication origins**: every account is `local`
  (password only) or `oidc` (SSO only). SSO accounts get the same generic
  login refusal as any bad credential and cannot set a local password; local
  login keeps working exactly as before and remains the break-glass path.
- **Dashboard**: the login page shows "Continue with SSO" when enabled
  (capability probe), and the public `/auth/sso/callback` page completes the
  handoff with human-readable error codes.
- **Audit**: `auth.oidc_login` / `auth.oidc_provision`.

## Security notes

- The identity key is the provider's `sub` claim — never email or username
  matching, and no silent linking of OIDC identities to local accounts.
- The browser only ever holds the Buz JWT. Provider tokens stay server-side;
  the callback→SPA handoff uses a 60-second, single-use, `HttpOnly` ticket
  cookie; `state` and tickets are stored hashed and are swept after use.
- A misconfigured `[auth.oidc]` disables only SSO — the server starts and
  local login is unaffected.
- `RUSTSEC-2026-0543` (chrono unmaintained, informational) accepted by policy
  in `.cargo/audit.toml` / `SECURITY.md`; no known vulnerability.

## Upgrade notes

- **Enable**: register the client at your provider with redirect URI
  `https://<buz-host>/api/v1/auth/oidc/callback` (exact string), scopes
  `openid profile email`, then fill `[auth.oidc]` in `manager.toml` (secret
  via `client_secret`, `BUZ_OIDC_CLIENT_SECRET`, or `client_secret_file`).
  See [OIDC Single Sign-On](/docs/01-architecture/platform/oidc-sso/).
- **JIT users get no access by default**: grant team roles with the existing
  RBAC after their first sign-in; set `auto_provision = false` to require
  pre-bound identities instead.
- Schema: SQLite migration 4 / Postgres migration 3 (applied automatically on
  the next start). No config or API breaking changes; existing local accounts
  and flows are untouched.
- Deferred to later phases: group → workspace role mapping, SCIM provisioning,
  RP-initiated logout, local→OIDC account conversion.

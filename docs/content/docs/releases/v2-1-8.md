## Added

- **Postgres is served for `[database] url = "postgres://…"`** when the
  Manager is built with the `postgres` feature and `[cluster] mode = "single"`.
  The schema, dual-dialect store, migration runner, and single-instance
  advisory lock are wired; every statement prepares against a real Postgres 14
  server. Official release binaries remain SQLite-only — build from source with
  `--features postgres` to serve Postgres.
- **Explicit Postgres serialisation** for every read-then-write invariant
  (pipeline, job, and runner row locks plus a first-admin advisory lock); the
  trigger and rerun concurrency decisions now happen inside the write
  transaction. See [Transaction Boundaries](/docs/01-architecture/execution/transaction-boundaries/).
- **`buz-manager migrate-sqlite-to-pg`** copies a fully migrated SQLite
  database into an empty Postgres target in one transaction with per-table
  count verification, an occupancy guard, and a source-schema version gate.
  `--pg-url` falls back to `BUZ_PG_URL`.

## Fixed

- **Concurrent `/setup` requests could create two first admins.** The re-check
  and insert now share a transaction-scoped lock on both backends.
- **`jobs.seq` / `audit_logs.seq` could collide under concurrent Postgres
  inserts.** The allocation triggers take an advisory lock; the second
  Postgres migration (v2) replaces the unlocked bodies.
- **`rotate-jwt-key` ignored `[database] url`** and could rotate a stale
  SQLite file on a Postgres-configured Manager. It now resolves the configured
  target, refuses Postgres, and does not create a missing database file.
- **`migrate-sqlite-to-pg` could read a stale source** when the config already
  pointed at Postgres. It now requires `--sqlite-path` in that case and
  refuses a source database that is not at this build's schema version.

## Changed

- **`[cluster] mode = "multi"` is refused at startup** for both backends.
  This build serves one Manager per storage; SQLite has no cross-instance
  coordination and Postgres takes a session advisory lock.
- `russh` upgraded to 0.65.1 (two low-severity advisories).

## Upgrade notes

- **Migrating an existing SQLite deployment:** start this build once against
  the SQLite file (it applies schema v3 and the definition backfill), stop it,
  keep the same `auth.jwt_secret`, then run `migrate-sqlite-to-pg` and switch
  `[database] url`. Full runbook: [Storage & Cluster Mode](/docs/03-operations/storage-cluster/).
- **Rotating the JWT key** remains SQLite-only; Postgres key rotation is not
  implemented.
- **Postgres requires a feature build**; the default binary fails closed on a
  `postgres:` url.

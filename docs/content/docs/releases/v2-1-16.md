## Added

- **Instance branding** — platform administrators can replace the built-in
  "Bz" mark with their own logo at **Settings → Branding**. The built-in mark
  remains the default: no upload means the UI looks exactly as it did, and
  *Restore built-in* puts it back. The image is served from
  `GET /api/v1/branding/logo` with a content-derived `ETag`, `nosniff`, and a
  restrictive CSP; the descriptor at `GET /api/v1/branding` is public because
  the sign-in pages need the logo before authentication. Product name,
  sidebar text, and theme are not editable here.

  Uploads are validated as PNG/JPEG/WebP/SVG by magic bytes (not just the
  declared MIME), capped at 512 KB, and SVG is screened against a reject list
  (`<script>`, `<foreignObject>`, `<!DOCTYPE`, `<!ENTITY>`, inline `on*=`
  handlers, off-document `href`s). Recommended asset: square, 512 × 512 px,
  transparent background, at least 10% safe margin.

- **SSO access policy** — a new card on Settings → SSO sets the user-JWT
  lifetime (`session_ttl_hours`, 1–720) and the client-side idle sign-out
  window (`session_idle_minutes`, 0 = off). Both live in `platform_settings`,
  so the existing DB-over-`manager.toml` override semantics apply. The
  lifetime is enforced server-side at token mint and affects tokens issued
  afterwards; the idle value is a SPA convenience, not a revocation — the
  token itself keeps its TTL.

- **SSO provider knobs** — token-endpoint client authentication can be chosen
  explicitly (`auto` keeps RFC 6749 discovery negotiation, otherwise force
  `client_secret_post` or `client_secret_basic`) instead of always trusting
  the provider's advertised list, and the claim name mirrored for display and
  audit is configurable (default `groups`). The mirrored groups carry no
  authorization.

- **Recent SSO events** — the Settings → SSO page lists platform-wide
  authentication events. Local password logins are deliberately excluded.

## Fixed

- **Settings → SSO showed one layout per instance history.** The page branched
  on `updated_by === ''`, so an instance that had never saved a configuration
  hid the *Sign-in policy* card and pushed *Register at your provider* into the
  320 px sidebar (reading as "it jumped to the far right"), while a
  previously-saved instance showed both in the main column. Every card now
  renders in both states with defaults: the strip reads *No configuration yet*
  instead of *Source: database*, the registration card is in the main column
  from the start (Callback falls back to the derived redirect URI the first
  save would store), and *Sign-in policy* is present with *Create on first
  sign-in* preselected. Before the first save the policy radios are a preview —
  the click is stored locally and travels with the next Save, because the
  immediate-save PUT would carry an empty issuer; the help text says which
  behaviour applies.

- **Idle sign-out could fire after ~30 seconds.** A policy payload without a
  numeric `idle_minutes` (a new dashboard against an older Manager, or a proxy
  answering with HTML) produced `NaN`; the "disabled" guard (`<= 0`) is false
  for `NaN`, so the timer armed and the first tick decided the browser was
  idle. The value is now validated (`Number.isFinite && > 0`) before the timer
  arms, with a regression test. The feature is cosmetic — it fails open.

- **Unknown `/api/v1/*` paths answered `200 text/html`,** because an unmatched
  API path fell through to the SPA fallback. They now answer the API's own JSON
  `404` (`{"code":2001,...}`), so a renamed route or a version mismatch between
  dashboard and Manager fails loudly instead of handing HTML to a JSON client.
  Client-side routes (`/dashboard`, …) keep serving the SPA.

- **SSO status no longer reads "Connection OK" on an issuer mismatch.** *Test
  connection* only proves the discovery document is reachable; the runtime
  additionally requires the advertised issuer to match the configured one
  character-for-character. When they differ (classically `localhost` vs
  `127.0.0.1`), the chip now says *Issuer mismatch* and a warning banner
  explains why sign-in is inactive.

## Changed

- `url` 2.5.8 → 2.5.9 ([RUSTSEC-2026-0592], stack overflow in `Url::origin()`
  on nested `blob:` URLs). Buz does not call `origin()` itself; the upgrade
  keeps the dependency tree clean.
- The repository root now ignores a stray `node_modules/` (Vite/Vitest cache,
  not a dependency tree).

[RUSTSEC-2026-0592]: https://rustsec.org/advisories/RUSTSEC-2026-0592

## Upgrade notes

- **Migrations v9 and v10 are plain additions** — a new `branding` table and
  two new `oidc_settings` columns. They run automatically on start and there
  is no down migration, but an older binary ignores the extra table and
  columns, so reverting to v2.1.15 does not break the schema. Back up the
  database as usual (`docs → Operations → Deployment`).
- **SSO is unchanged for existing deployments.** `[auth.oidc]` in
  `manager.toml` is still imported into the database once and afterwards
  ignored; nothing needs to be re-entered on upgrade.
- Per-release notes live in the docs; the full design sits in
  `Architecture → Platform → oidc-sso` and the new `branding` page.

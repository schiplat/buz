## Added

- **RP-initiated logout**: the dashboard "Sign out" now also ends the
  identity-provider session. After clearing the local JWT, the browser is
  sent to `GET /api/v1/auth/oidc/logout`, which renders the standard
  auto-submitting form POST to the provider's `end_session_endpoint`
  (discovered) with `client_id` and the registered
  `post_logout_redirect_uri` — no `id_token_hint` (Buz never stores provider
  tokens; the POST form is the cross-site-safe variant). The provider
  returns the browser to the new `/auth/sso/logged-out` landing page.
  - SSO off → straight to the login page; a provider without an advertised
    end-session endpoint → purely local sign-out (previous behavior).
- **Token-endpoint client authentication is negotiated from discovery**:
  `client_secret_post` when the provider declares it (unchanged default,
  also the fallback when discovery is silent), `Authorization: Basic`
  otherwise. Providers accepting both work with either.
- The Settings → SSO page now lists all three provider registrations derived
  from `server.public_base_url`: the callback, the back-channel logout URL,
  and the post-logout landing.

## Changed

- **The database is now the only SSO configuration source.** The
  `[auth.oidc]` section in `manager.toml` no longer feeds the runtime: at
  startup a valid file section with no database row is **imported into the
  database once** (secret re-encrypted at rest, row stamped `file-import`,
  announced in the log) and afterwards ignored — remove the section from
  `manager.toml` after upgrading. New deployments configure SSO in the web
  UI only. `DELETE /api/v1/auth/oidc/settings` now **clears** the
  configuration (SSO off until saved again) instead of falling back to the
  file seed.

## Upgrading

Optional: register `{server.public_base_url}/auth/sso/logged-out` as the
client's `post_logout_redirect_uri` at your OIDC provider to get the
round-trip landing. Without it, sign-out still ends the provider session
but the browser may stay on the provider's page. If `manager.toml` still
carries `[auth.oidc]`, remove it after the first boot — the import has
moved everything into the database.

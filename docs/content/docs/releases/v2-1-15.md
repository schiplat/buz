## Added

- **`buz-manager check-data`** — read-only report for team-binding rows the
  write-path guards can no longer create: pipelines/secrets with an empty or
  unknown `team_id`, hosts with an unknown `team_id`, and `pipeline_secrets`
  rows spanning two teams. The Manager logs one warning at startup when the
  report is not clean.
- **Hello Buz sample pipeline** — fresh installs receive one editable sample
  pipeline. `buz-manager seed-sample` restores it after deletion; it never
  duplicates an existing sample.

## Changed

- **Team ownership is normalized.** `team_id` is the only stored identity:
  SQLite schema v8 / PostgreSQL schema v7 materialise teams for legacy
  `owner_group` slugs, backfill `team_id`, drop the duplicated `owner_group`
  columns, and rename `secrets.team_shared` to `share_with_team`.
- **Name scoping follows the owner.** Secret names are unique per
  `(team_id, name)`; host names are unique per owner (team, or the platform
  tier). Two teams may each own the same name. API responses keep
  `owner_group` as the derived team slug; input `owner_group` (API and YAML)
  remains a deprecated alias for `team_id` / `team:`.
- **Dashboard surface system.** Cards, insets, overlays, modals, inputs,
  selects, notices and status chips now share one recipe: one outline per
  surface, soft shadows, a 16/12/8 radius scale, `/40` neutral fills and
  semantic `/10` tones. All native selects use one control with a single
  chevron, and Stage View step cards have clearer borders with a larger
  fixed layout and capped fit zoom.

## Fixed

- A secret cannot change teams while bound to pipelines; the 409 names the
  affected pipelines so the caller can unbind first.
- Deleting a team now counts team-scoped hosts and reports them instead of
  leaving invisible rows and stored credentials behind.
- The team-delete conflict is surfaced in the dashboard instead of failing
  silently.

## Breaking changes

- `POST` / `PUT /api/v1/secrets` read `share_with_team`; `team_shared` is
  ignored and responses use the new field.
- Direct SQL or reporting that selected `pipelines.owner_group` /
  `secrets.owner_group` must join `teams` on `team_id`. YAML `owner_group:`
  remains a deprecated alias for `team:`.
- The first start applies the schema migration automatically. Take a database
  backup first — there is no down migration. Verify afterwards with
  `buz-manager check-data`; the Deployment docs describe the procedure.

## Upgrade

Stop the Manager, back up the database, start the new build, then run
`buz-manager check-data`. Legacy owner-group slugs are materialised as teams
before the columns are dropped; unknown team ids are reported for manual
repair.

## Added

- **Identity approval queue**: with `auto_provision = false`, a refused
  sign-in no longer dead-ends. The refused identity
  (`(provider, subject)`, email, name, groups) is recorded and refreshed on
  every attempt, and a platform admin resolves it from the Users page:
  - **Bind to an existing account** — the identity attaches to the chosen
    local user. The account keeps its local password unless the admin
    explicitly disables it (SSO-only flip). The last active local platform
    admin's password can never be disabled through this path (break-glass).
  - **Create a plain SSO user** — same shape as JIT provisioning (no teams,
    no admin flags, no local password), username derived from the claims or
    chosen explicitly.
  - **Dismiss** — a later attempt re-records it (the queue is not a
    blocklist).
  Both outcomes are audited (`auth.oidc_identity_approve` /
  `auth.oidc_identity_reject`); binding runs in one transaction with clear
  conflicts (identity already bound, user already carries an identity,
  disabled user). Binding is an explicit admin assertion on a verified
  `sub` — never an email match.
- **Admin identity views**: the Users list now carries `auth_source`
  (`local` / `oidc`) and the dashboard shows an SSO badge per account.
- New table `pending_identities` (SQLite migration 7 / Postgres migration
  6); queue rows are display data only and never influence sign-in
  decisions.

## Fixed

- The SQLite → Postgres data-migration tool skipped the OIDC tables
  (`external_identities`, `sso_flows`, `sso_tickets`) silently — a backend
  switch dropped SSO bindings and flow state. `TABLE_ORDER` now enumerates
  them (plus `pending_identities`), and the tool's table guard refuses an
  incomplete source.

## Upgrading

No behavior change for `auto_provision = true` deployments (the default).
With auto-provision off, identities that sign in now appear in the Users
page queue awaiting approval.

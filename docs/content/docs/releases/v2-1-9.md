## Fixed

- **A concurrent cancel could overwrite a promoted approval outcome on
  Postgres.** `cancel_job_in_tx` read the job snapshot before its guarded
  `UPDATE`; an approval that committed in between could replace the promoted
  `approved` outcome with `cancelled` in the same row. The cancel path now
  takes the job row lock before the read, matching approve/reject. SQLite was
  already serialised by `BEGIN IMMEDIATE`, so this affected Postgres feature
  builds only.

## Upgrade notes

- **Postgres feature builds:** use 2.1.9. The v2.1.8 release binaries are
  SQLite-only (the default build) and are not affected by this race.
- No schema, config, or API changes.
